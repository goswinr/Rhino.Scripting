# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository.

## Project

Rhino.Scripting is an F# translation of McNeel's IronPython [rhinoscriptsyntax](https://github.com/mcneel/rhinoscriptsyntax) for the Rhino3D CAD app, usable from F# and C#.
All ~900 functions are static methods on one class, `Rhino.Scripting.RhinoScriptSyntax`.
Behavior should follow the Python original unless a change is intended; such changes are recorded in CHANGELOG.md.

## Build and verify

```bash
dotnet build ForEditing.fsproj          # net48 only, fast, use while editing

dotnet fsi combineIntoOneFile.fsx       # run once first, see below
dotnet build ForPublishing.fsproj -c Release   # net8.0 + net48, also packs the NuGet package
# or one framework at a time:
dotnet build ForPublishing.fsproj -c Release --framework net8.0
```

- `global.json` pins the .NET 10 SDK, and all workflows install the SDK from it. `fsdocs-tool` needs the .NET 10 runtime too.
- Pass `-c Release` explicitly. The project file deliberately doesn't set the configuration, because a value set there comes too late to switch on optimization.

- There are no tests and no linter. The library only works inside a running Rhino process (`State.Doc` raises otherwise), so verification means compiling both projects without new warnings. `--warnon:3390` (XML doc completeness) and `--warnon:1182` (unused variables) are on.
- Both `ForPublishing.fsproj` frameworks run `combineIntoOneFile.fsx` before compiling. Built together, they can race writing the generated file. Running the script first (as CI does) avoids that, because it skips writing when the content is unchanged.
- Building `ForPublishing.fsproj` also copies README.md to `Docs/index.md` (gitignored), which the docs need.

Docs (needs a Release build of `ForPublishing.fsproj` first; `fsdocs-tool` must keep `rollForward: false` in `.config/dotnet-tools.json`):

```bash
dotnet tool restore
dotnet fsdocs build --clean --strict --properties Configuration=Release --input Docs --output DocsGenerated
```

## Architecture: one class, many files

F# extension members are not visible from C#, so every public method must be an intrinsic member of `RhinoScriptSyntax` in a single file. Editing a 20k-line file is too slow for tooling, so the source is split:

- `Src/Scripting_Header.fs` declares `type RhinoScriptSyntax` and all the `open` statements.
- Each other `Src/Scripting_*.fs` file is `[<AutoOpen>] module AutoOpenXxx =` / `type RhinoScriptSyntax with`, followed by the split marker comment `{@$%^&*()*&^%$@}` and then the members.
- `ForEditing.fsproj` compiles these files separately, so the members are extension members.
- `ForPublishing.fsproj` runs `combineIntoOneFile.fsx`. It appends everything from the marker line onward of each file to the header, producing `Src/AutoGeneratedCode/AllScriptingFilesCombinedIntoOne_DontEditThisFile.fs`, which is compiled instead.

Consequences:

- Never edit the generated file. It is checked into git: rebuild `ForPublishing.fsproj` (or run the script) after changing a `Scripting_*.fs` file, then commit the regenerated file with the change. `build.yml` fails if it is out of date.
- Everything above the marker is discarded. Any `open` a member needs belongs in `Scripting_Header.fs`. Members stay indented 4 spaces so they line up with the class body once combined.
- In `ForEditing.fsproj`, a member can only call members from files earlier in compile order. Coerce and Layer come first for that reason. Call other members as `RhinoScriptSyntax.Xxx(...)`.
- A new `Scripting_*.fs` file must be added to `ForEditing.fsproj` and to the `files` list in `combineIntoOneFile.fsx`. The script fails the build if those lists, or the `Src/` folder, disagree, or if a marker is missing.

The infrastructure files (`Exceptions.fs`, `Utils.fs`, `RhinoSync.fs`, `State.fs`, `Pretty.fs`, `UtilString.fs`, `UtilLayer.fs`, `ObjectFilterEnum.fs`) are compiled normally by both projects, in that order. They live in the namespaces `Rhino.Scripting` and `Rhino.Scripting.RhinoScriptingUtils`. `State` (internal) lazily finds the active `RhinoDoc` on first access and tracks document changes and Esc presses through Rhino events. The assembly declares `InternalsVisibleTo Rhino.Scripting.FSharp`, so internal helpers are used by that companion package; renaming them can break it.

## Rhino 7 vs Rhino 8

- net48 compiles against RhinoCommon 7.0 with the `RH7` define. net8.0 compiles against RhinoCommon 8.19 (it ships only net7.0 and net48 assemblies). RhinoCommon and Eto.Forms are compile-time references only; the user's Rhino provides them at runtime.
- `ForEditing.fsproj` only builds net48. Rhino 8-only APIs must sit in the `#else` branch of `#if RH7 ... #else ... #endif`, and only `ForPublishing.fsproj` (net8.0) compiles that branch.

## Threading

Methods can be called from any thread. Code that touches UI (dialogs, layer creation, interactive picking) is wrapped in `RhinoSync.DoSync (fun () -> ...)`. Methods that prompt the user in the viewport use the `let get () = ...` / `RhinoSync.DoSyncRedrawHideEditor get` pattern, which also hides the Fesh editor window during the pick.
`RhinoSync` finds the [Fesh.Rhino](https://github.com/goswinr/Fesh.Rhino) plugin by reflection: its plugin GUID, the type `Fesh.Rhino.Sync` and that type's property names. Fesh also calls the `initialize` field by reflection, so do not rename it. Without Fesh, `RhinoSync` falls back to `Eto.Forms.Application.Instance.Invoke`.

## Conventions

- Python's dynamic arguments become overloads: getter, setter, and a multi-object setter. The signature line carries a trailing comment `//GET`, `//SET`, `//MULTISET` or `//PLURAL`.
- Optional parameters use `[<OPT;DEF(value)>]` (`OptionalAttribute` and `DefaultParameterValueAttribute`); nulls need a type, e.g. `DEF(null:string)`. A parameter that tells overloads apart must not be optional (see `Add` in `Scripting_Header.fs`).
- XML docs follow this pattern: `<param name="x">(type) Optional, default value: <c>v</c>. Text</param>` and `<returns>(unit) void, nothing.</returns>`. The docs build runs with `--strict`.
- Errors: `RhinoScriptingException.Raise "MethodName: ... '%s'" arg` (printf-style; the `RhinoScriptSyntax.` prefix and version info are added automatically). Use `RaiseWith inner` to keep an inner exception, and `RhinoUserInteractionException` when the user cancels input. Prefer raising over returning `Guid.Empty` or null. `TryCoerce*` functions return an option and never throw.

## CHANGELOG and releases

- The package version comes from the top release in CHANGELOG.md (via `Ionide.KeepAChangelog.Tasks`). Add entries under `## [Unreleased]` in `### Added`, `### Changed` or `### Fixed`, and start breaking changes with `Breaking:`.
- The changelog parser breaks the build on bullets that span lines, on nested bullets, and on mixed line endings. Keep each bullet on one line and keep the file's existing line endings.
- Pushing a git tag `X.Y.Z` runs `.github/workflows/releaseNuget.yml`, which fails unless the tag equals the CHANGELOG version.

## Other folders

- `Tools/*.fsx` are one-off scripts from past bulk edits of the source (docstring fixes, file splitting). They are not part of the build.
- `.claude/skills/rhino-scripting.md` is an end-user guide to writing scripts with this library, not to developing it.
